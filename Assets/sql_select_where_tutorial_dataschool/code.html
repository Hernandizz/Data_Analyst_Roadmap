SQL: Memilih dan Memfilter Baris Data (SELECT & WHERE)

Dalam pekerjaan harian data analyst, Anda jarang membutuhkan keseluruhan tabel database. Klausa SELECT mendefinisikan kolom metrik yang ingin Anda evaluasi, sedangkan klausa WHERE menyaring baris berdasarkan kriteria bisnis spesifik dari jutaan rekaman mentah dalam hitungan detik.

filter_alt Filter Presisi Hanya baris dengan kondisi TRUE yang dikembalikan mesin SQL.
speed Hemat Bandwidth & Biaya Memangkas beban komputasi di cloud warehouse seperti BigQuery.
dataset Ekstraksi Bersih Output siap langsung dikonversi ke format DataFrame Pandas.

Sintaks Dasar

Standar ANSI SQL

Struktur penulisan query filter mengikuti urutan logis: pilih kolom yang dibutuhkan, sebutkan tabel sumber, lalu tentukan kondisi filter pada baris data.

syntax_pattern.sql
1 SELECT customer_name, city, total_spent
2 FROM orders
3 WHERE status = 'Completed' AND total_spent >= 500000;

Tabel Operator Logika & Perbandingan

Kamus Lengkap Filter SQL

Gunakan operator komparasi berikut di dalam klausul WHERE untuk mengisolasi baris data yang relevan:

Operator Contoh Penggunaan Deskripsi & Logika Bisnis
= country = 'Indonesia' Pencocokan persis (exact match). Mengambil nilai yang sama identik.
!= atau <> status != 'Cancelled' Tidak sama dengan. Menolak baris transaksi yang dibatalkan pengguna.
>, <, >=, <= age >= 21 AND score < 80 Perbandingan numerik atau rentang tanggal kronologis.
BETWEEN price BETWEEN 100 AND 500 Termasuk nilai batas atas dan batas bawah (inklusif range).
IN (...) city IN ('Jakarta', 'Bandung') Mengevaluasi kesamaan anggota terhadap daftar nilai kategori jamak.
LIKE email LIKE '%@gmail.com' Pencocokan pola string (wildcard). Simbol % mewakili 0 atau banyak karakter.
lightbulb
Catatan Praktik Lapangan (Analyst Tip: Sargability & Biaya Query) Best Practice

Hindari membungkus kolom dalam fungsi matematis atau string di klausul WHERE jika tidak mendesak. Contoh: Jangan gunakan WHERE YEAR(order_date) = 2024 karena indeks database menjadi tidak aktif (*non-sargable query*), sehingga database harus memindai (*full-table scan*) seluruh miliaran baris.

Alternatif Lebih Cepat: Gunakan WHERE order_date >= '2024-01-01' AND order_date < '2025-01-01'. Pada platform BigQuery atau Snowflake, kebiasaan ini dapat menghemat anggaran komputasi hingga 80%.
